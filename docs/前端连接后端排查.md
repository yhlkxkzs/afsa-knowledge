# 前端连不上后端 — 排查步骤

## 1. 确认后端已启动且本机可访问

在**运行后端的机器**上执行：

```bash
curl http://127.0.0.1:32222/health
curl http://127.0.0.1:32222/knowledge/filters
```

若返回 JSON（如 `{"status":"ok"}`）说明后端正常。若连不上，先执行 `./run_unified_api.sh` 启动统一 API。

---

## 2. 前端使用的地址必须正确

- **前端和后端在同一台电脑**（如本机浏览器访问本机后端）  
  使用：`http://127.0.0.1:32222` 或 `http://localhost:32222`

- **前端在手机或另一台电脑**（如手机 App、其他机器的浏览器）  
  必须用**服务器的局域网 IP**，不能用 `127.0.0.1`（那是前端设备自己）。  
  例如服务器 IP 为 `192.168.1.7` 时，baseUrl 填：`http://192.168.1.7:32222`

查看服务器 IP（在服务器上执行）：
```bash
hostname -I | awk '{print $1}'
```

---

## 3. 防火墙是否放行 32222

在**服务器**上检查并放行端口（示例，按实际系统调整）：

```bash
# 查看是否在监听
ss -tlnp | grep 32222

# 若使用 firewalld（如 CentOS/RHEL）
sudo firewall-cmd --add-port=32222/tcp --permanent
sudo firewall-cmd --reload

# 若使用 ufw（如 Ubuntu）
sudo ufw allow 32222/tcp
sudo ufw reload
```

---

## 4. 前端配置检查

- baseUrl / API 根地址 必须包含：**协议 + 主机 + 端口**
  - 正确示例：`http://192.168.1.7:32222`
  - 错误示例：`http://192.168.1.7`（缺端口）、`https://...`（后端是 http 时可能被混合内容策略拦截）

- 统一网关下路径为：
  - 知识库：`/knowledge/filters`、`/knowledge/items`、`/knowledge/items/<id>`
  - 识别：`/predict`、`/health` 等（无前缀）

---

## 5. 快速测试（在连接前端的设备上）

- 浏览器打开：`http://<服务器IP>:32222/health`  
  若能看到 `{"model_loaded":true,"status":"ok"}` 说明网络和端口都通，问题多半在前端配置的 baseUrl 或路径。
