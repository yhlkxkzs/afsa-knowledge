# 个人仓与数据分层管理

App 侧涉及 **三类 GitHub 仓** + **本地统一 API**。个人仓不应与推理仓、知识库仓混用。

## 1. 仓的角色划分

| 仓类型 | 命名示例 | 生命周期 | 谁有写权限 | 统一更新方式 |
|--------|----------|----------|------------|--------------|
| **推理仓** | `fruits-classifiaction-for-afsa`、`afsa_disease-recognition` | 长期 | 维护者 | `install_to_repos.sh` / 组织模板 PR |
| **知识库仓** | `yhlkxkzs/afsa-knowledge` | 长期 | 维护者 | 维护者 push + App 读 API |
| **用户个人仓** | `{github_user}/afsa-incoming-{suffix}` | 按数据分层 | **用户 OAuth** | 见 §4 |
| **共享收集仓** | `yhlkxkzs/incomingpictureforafsa` | 长期 | 策略定 | 维护者 |

文档约定：推理结果走推理仓 Actions；**用户原始图集**进 `afsa-incoming-*`，不进推理仓。

## 2. 个人仓内数据分层（核心）

同一用户仓内用 **路径 + sidecar 字段** 区分 TTL 与长期数据：

```text
{user}/afsa-incoming/
├── logs/                          # 短期：操作/识别日志（TTL）
│   └── YYYY/MM/
│       └── events.jsonl
├── orchard/                       # 长期：果园档案
│   ├── profile.json               # 品种、位置、面积、建园年
│   ├── blocks/                    # 地块
│   └── seasons/                   # 农事记录
├── uploads/                       # 长期：用户主动保存的图（可选 TTL 归档）
│   └── disease/...
└── incoming/                      # 中期：待推理队列（与 GitHub Actions 对接时可镜像）
    └── disease/uploads/
        ├── xxx.jpg
        └── xxx.afsa.json
```

### sidecar 扩展建议

```json
{
  "schema_version": 2,
  "task_type": "disease_classification",
  "data_tier": "inference_queue",
  "retention_days": 30,
  "afsa_detection_id": "rec_...",
  "orchard_block_id": "block_a3"
}
```

| `data_tier` | 含义 | 建议保留 |
|-------------|------|----------|
| `log` | 上传/识别/点击日志 | **7–90 天**（可配置） |
| `knowledge_read_log` | 知识库曝光/阅读（`logs/knowledge_reads/*.jsonl`） | **90 天**（`retention_days`） |
| `inference_queue` | 等 Actions 推理的图 | 推理完成后 **30 天** 归档或删 |
| `upload_archive` | 用户明确「保存」的图 | **长期** |
| `orchard` | 果园主数据 | **长期** |

## 3. TTL 日志 vs 长期果园：怎么实现

GitHub 仓本身 **没有内置 TTL**。需要 **App + 维护者后台** 共同实现：

### 方案 A：App 端生命周期（推荐起步）

1. 写 log 时路径带日期：`logs/2026/05/event-{id}.jsonl`
2. App 启动或每周任务：删除 `retention_days` 之前的 `logs/**`
3. `orchard/**` 永不自动删；仅用户「删除账号/地块」时删

### 方案 B：GitHub Actions 定时清理（你有 maintainer 权限时）

在用户仓放 `.github/workflows/retention-sweep.yml`：

```yaml
on:
  schedule:
    - cron: '0 3 * * 0'   # 每周日
jobs:
  sweep:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: python3 .github/scripts/afsa_retention_sweep.py
```

脚本按 `data_tier` / 路径规则 delete 过期 `logs/`、`incoming/` 已推理条目。

### 方案 C：元数据在本地 API，文件在 GitHub

- **果园、账号**：SQLite / Postgres（长期）
- **日志**：本地 `upload_log.jsonl` + 定期 truncate（已有雏形：`api_mobilenet.py`）
- GitHub 只存用户明确要云端备份的图片

## 4. 你对「用户个人仓」有没有控制权限？

| 方式 | 你能做什么 | 限制 |
|------|------------|------|
| **用户 OAuth（当前设计）** | 不能读/删用户私有仓内容 | 仅用户 token 可写其 `{user}/afsa-incoming-*` |
| **GitHub App（组织安装）** | 组织内批量装 workflow、只读 audit、可选 write | 需用户/组织授权安装 |
| **维护者被加为 collaborator** | 对该用户仓 read/write | 不可扩展，不适合规模化 |
| **中心化服务账号** | 代用户建仓、代 push（需用户 consent） | 合规与 token 托管成本高 |

**结论**：文档里的 `{user}/afsa-incoming-*` 默认 **你没有任意控制权限**；要实现「统一更新、TTL 清扫」，应：

1. 发布 **模板仓** `yhlkxkzs/afsa-incoming-template`
2. 用户 Fork 或通过 GitHub App 从模板创建
3. 用 **GitHub App** 或 **workflow_dispatch** 向已登记用户仓发 PR 更新 `.github/` 与 `orchard/schema.json`

维护者侧维护 **`users/registry.json`**（不在用户仓内）：

```json
{
  "users": [
    {
      "app_user_id": "u_001",
      "github_login": "farmer_zhang",
      "incoming_repo": "farmer_zhang/afsa-incoming-main",
      "installed_template_version": "2026.05.1",
      "log_retention_days": 30
    }
  ]
}
```

## 5. 多用户个人仓：组织方式与统一更新

```text
                    ┌─────────────────────────┐
                    │  afsa-incoming-template  │  ← 维护者唯一维护
                    │  (.github + schemas)     │
                    └───────────┬─────────────┘
                                │ fork / app create
          ┌─────────────────────┼─────────────────────┐
          ▼                     ▼                     ▼
   userA/afsa-incoming    userB/afsa-incoming    userC/...
          │                     │
          └────────── registry (维护者 DB) ────────┘
                                │
                    batch PR bot / GitHub App
                    更新 workflow + retention 脚本
```

**统一更新步骤**：

1. 改模板仓 `afsa-incoming-template` 的 `.github/workflows/`、`scripts/afsa_retention_sweep.py`
2. 跑 `scripts/fleet_sync_incoming_repos.py`（待建）：读 registry → 对每个 repo 开 PR「Bump template to vX」
3. **推理仓** 与 **个人仓** 分开 sync（已有 `install_to_repos.sh` 只管推理仓）

**不要**用个人仓承载全局知识库或模型权重。

## 6. 与知识库、识别模型的关系

| 数据 | 存放位置 |
|------|----------|
| 病害/虫害 **知识正文** | `afsa-knowledge`（维护者） |
| 知识库 **配图** | 本地 `disease_recognition` 高质量样本 + `dataset_catalog.json` 溯源 |
| 识别 **模型** | 各推理仓 `exports/` |
| 用户 **识别一次的结果** | Actions artifact（短 TTL）→ App 本地持久化 |
| 用户 **果园与日志** | 个人仓分层 或 后端 DB |
